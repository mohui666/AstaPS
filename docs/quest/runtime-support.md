# 剧情任务的服务端支持边界

这些记录描述已实现的服务端机制，不代表相关章节已经完成客户端连续通关。

## 已接入的共用路径

- 场景到达、离开任务范围、须弥梦境允许进入的房间、全局剧情变量和父任务状态，按玩家当前的服务端状态判定。与对话等目标组合时重新检查状态；副本通关等事件目标仍累计保存进度。
- 尚未完成或失败的多目标任务，在目标进度实际变化时保存父任务；重复事件不重复写入，避免只通知客户端却丢失重登进度。
- 无法解析的任务条件保留为 `UNKNOWN`，不会因为解析失败而减少条件数量，也不会把未知接取条件变成无前置任务。
- 指定机关的状态变化同时匹配场景组、机关配置编号和目标状态。
- `CHANGE_SKILL_DEPOT` 使用旅行者候选技能组下标，不能把下标 `3` 当作草元素编号；`UNLOCK_AVATAR_TEAM` 只收回当前父任务授予的试用角色。
- 动态场景组注册等待场景脚本初始化，并保存所属任务的场景组记录；任务流场景组刷新复用原有 suite 切换路径。
- 批量功能开关先校验完整的编号和值列表，再逐项应用。
- 稻妻主线 `201002` 与森林书 `7302521` 的浪船创建使用原生坐标。同一玩家、同一载具类型、同一出生点重复创建时复用实体；清理只移除该玩家的载具。
- 任务范围、剧情传送和重登回退先使用已有坐标索引；索引缺失时读取当前场景的原生 `dummy_points` Lua。已核实旧索引缺少的 `Q3007CityCenterPos`、`Q7302521_guide` 在当前 Lua 中存在。
- Lua 的 `GetGroupTempValue` / `SetGroupTempValue` 支持当前组、`group_id` 和数组形式的指定组。临时值按场景、场景组隔离，卸载场景组时清除，不写入持久化场景变量。
- 进入其他玩家世界不触发“返回自己的世界”任务目标。

新增的服务端状态条件采用独立内部编号；其 7.1 客户端线协议编号尚未验证，不能将内部编号用于构造客户端上报。

## 仍未完成

后续主线仍有镜像队伍、纳塔战争控制、枫丹证据物品、天气区域及场景标签等独立机制需要实现。部分新协议在现有资料中尚无已验证的名称及字段映射，不能用空处理器宣称支持。

森林书目前只覆盖上述坐标、浪船和 Lua 临时计数等共用修复。兰那罗收集、梦境与天气状态、无留陀战斗涉及的其他脚本接口仍未完成全链路验证，不能列为完整可玩。

回归应继续按主线优先、重要世界任务其次的顺序进行；构建和自动化测试通过后，仍需使用对应客户端验证连续对话、战斗、副本、重登和结算。
