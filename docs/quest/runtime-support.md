# 剧情任务的服务端支持边界

本版包含下述主线、森林书和重要世界任务机制。章节名称、任务数量和已知缺口见[剧情清单](story-catalog.md)。配置存在、自动测试通过、客户端整章通关是不同证据；本次没有进行客户端连续通关验收。

本版关卡重建需要同时应用[配套资源增量](../../tools/quest-resource-patches/README.md)，其中包含外部 Lua、邀约和场景资源。

## 森林书

《林中奇遇》《梦中的苗圃》《失梦的苗圃》《最终，森林会记住一切》及《愿为一炊之梦》《吉祥具书》《水天供书》《正法炬书》的共用机制已修复到上述测试覆盖范围。`73014–73017` 的四个流程组均有真实 `io_type=1/sub_flow_type=1` 和阶段配置。

仍需实机验证连续对话、梦境画面、机关与平台、魔王战阶段衔接、过场、重登和最终结算，当前不能标为“森林书全部保证可玩”。历史快照若存在同组、同配置的重叠怪潮且不能确定实体归属，清理明确失败，避免误删其他潮次。

通用关卡的可编辑源是[QuestStoryReconstruction.json](../../src/main/resources/defaults/data/QuestStoryReconstruction.json)。每项保留任务号、原通知键、坐标依据和重建说明；只有明确列入该表的任务会采用重建逻辑，未知任务不会自动变成通用试炼。运行时验证实际玩家、实体、距离和当前任务，客户端单条或批量计数不能代替服务端持有的玩法目标。

调整通用清单后，在仓库根目录运行：

```powershell
node tools/quest/generate-reconstructed-scenes.cjs
```

生成器只更新本任务标记的group/block与场景索引追加段，拒绝覆写既有业务脚本；保留spawn的原组仍由原block持有，不重复注册。服务端代码与外部`resources`独立维护，需配套应用本版资源增量。

## 原版差异与实机边界

上表标明的玩法、分支、时限和模型替代均不代表完整官方实现；TPS完整官方成长流程、原七圣技能引擎、原钓鱼与捕捉UI、旧送餐能力状态判定仍有差异。自动测试不能替代客户端连续对话、演出、模型与整章存档验收，当前不作“所有剧情全部保证可玩”的结论。

## 验证和来源

本次公开候选在独立发布工作区完成 Java 21 主源码及测试源码编译，341 类 2054 项非集成测试全部通过（零失败、错误和跳过），复用对应版本的已生成协议类。配套资源增量通过与已修复资源的反向匹配检查，一键连接器通过 PowerShell 语法检查。未进行客户端整章通关或好友双端 PvP 验收。

本轮已知的原任务执行器、接取条件和完成/失败条件类型均有对应处理；其中明确列出的缺失玩法采用上表重建规则，处理器索引本身不能证明整章可玩。

验证覆盖真实Lua资源加载、任务动作、Gson与Morphia二进制BSON编码往返、正常请求处理链和原生线协议；BSON编码验证未连接MongoDB，未进行真实数据库存取往返或客户端整章通关，不将自动化验证当作实机通关证据。

服务端行为依据为固定的[3.4原生源码](https://github.com/Havesten/hk4e-sources/tree/d12e0ae8dbe6012aefca71128d4c13e48113b68d/data/jenkins/jenkins_hk4e/workspace/hk4e_3.4_dev/gameserver/src)：`player/quest/player_quest_comp.cpp`、`player/quest/parent_quest.cpp`、`script/script_lib.cpp`、`group/group.cpp`、`group/monster_tide_comp.cpp`、`scene/player_view_mgr.cpp`和`scene/scene_misc_comp.cpp`。7.1补充协议另按匹配的Global Windows x64客户端解析器和消费者核实，字段保存在[compat](../../protocol/7.1/compat)并有相应线协议测试；不把3.4协议编号直接用于7.1。
