# MGC 深渊战斗资源生成

在服务端根目录执行：

```powershell
python tools/tower/generate_current_abyss.py --resources resources --schedule-id 124
```

输入为本机资源包的 TowerSchedule、TowerFloor、TowerLevel、Dungeon、Monster、MonsterDescribe 和被引用的 MonsterPreview JSON。PT18 需先从自己的官方客户端导出并解码，不随此工具分发。

敌人种类、等级来自实际客户端预览；数量、波次和同时在场上限根据[原神 BWIKI 第58期](https://wiki.biligame.com/ys/index.php?title=渊月螺旋&oldid=689651)核对，保存在 `schedule_124.json`。9~12 层合计 141 只敌人，补位关卡每击败一只立即补位，正式波次之间等待当前波清空。9-2 的冰、火兽怪使用独立元素变体。坐标和百科未列出的具体补位顺序由 MGC 编写。

输出保留现有场景文件，只补 `resources/Scripts/Scene/` 下的 block/group。已有非本工具脚本会拒绝覆盖。怪物变体选择、各波站位、并发上限和来源写入同目录 `mgc-schedule-124.json`。其他期数需要同时传入与 `--schedule-id` 匹配的 `--battle-plan`。

重复执行会覆盖仍保留首行生成标记的文件，不检查其内容是否被人工修改。需要手工编辑时先删掉首行 `-- Generated by MGC ...`，生成器便会拒绝覆盖该文件。

普通房复用现有深渊的 175/176 工作台、197/198 挑战、剩余时间与换队流程。11-1 以 188 守护挑战保留同一镇石（group `233899003`、config `3024`），使用原始 20/40/60% 星级条件。上下半场始终留在同一副本场景。Lua 为 MGC 自编，百科统计也不等于已取得官方服务端脚本。

12-1 上半箭士的闪现保护按本机 `Invisible_CountDown` 的 2 秒时长结束，服务端清理该闪现实例的无敌与禁止锁定状态，保留其他保护状态。此处修复服务端残留状态；伤害恢复仍需用真实客户端战斗确认，不能用离线测试代替。

12-1 上半明确采用秘境变体 `25133802`，生命值设置为 **5,535,346**，来源为[玉璃的 12-1 数据](https://alioth.wiki/gi/monster/51338)。本机 95 级曲线 `3344.277099609375` × 秘境变体基础生命 `348.4567565917969` × `4.75` 与此数值一致。旧的地方传奇变体 `25133801` 配合旧倍率会生成 12,492,881 血；现通过脚本 `max_hp` 仅覆写此关的实体，不改全局 MonsterData。单体首领发送原生精英显示标记与当前怪物表的称号、特殊名称 ID，顶部血条样式仍需客户端确认。

当前进度通知的字段 9 为楼层配置 ID，字段 10 为 1–3 的间数。原生成协议的这两个名字相反；客户端原生解析与 TowerModule 的楼层查表调用已静态核对，手写通知按实际字段含义发送。
